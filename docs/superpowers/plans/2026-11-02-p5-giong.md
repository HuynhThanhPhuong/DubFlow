# P5 Giọng — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Produce real Thuyết minh (TM) and Lồng tiếng (dub) exports.
- **TM:** OmniVoice reads with one stock voice; VoxCPM2 is the fallback.
- **Dub:** VoxCPM2 in mix mode; OmniVoice is the fallback.
- **Pick order:** text match, then ECAPA voice similarity, then duration fit.
- **Report:** a per-line note of which engine produced each line.

**Architecture:** synthesis keeps its per-line candidate loop (gen → Whisper pick), but generation goes through an *engine* field.
- `gen` (VoxCPM2, tts venv) and a new `gen_omni` (OmniVoice, `D:/OmniVoice/venv` read-only = `asr_python`) each write takes to `lines/`.
- `pick` checks text.
- A new `similarity` stage (speaker venv, ECAPA) scores the passing takes against the line's reference.
- `synthesize` chooses each line's take and writes `voice-report.json`.

**Tech Stack:** Python. VoxCPM2 (repo-tests/clone-voxcpm), OmniVoice 0.2.1 (D:/OmniVoice/venv, HF_HOME D:/OmniVoice/cache/hf, offline), Whisper large-v3-turbo, speechbrain ECAPA (repo-tests/models/speaker-ecapa-voxceleb, speaker venv).

**Spec:** `docs/superpowers/specs/2026-11-01-dubflow-web-v2-design.md` §6.5, §8 (6.5). The user's decisions of 2026-11-02 override §6.5 for TM: OmniVoice is primary for TM. They also add the short-line rule.

## Global Constraints
- `D:\OmniVoice` is read-only: run its python, never write there. Set TMP/TEMP and output dirs inside the job directory.
- Never have two GPU models loaded at once. Stages run as separate subprocesses, one after another, as they do today.
- Natural speed: no atempo, no cropping (keep `place()` behaviour).
- **Text match:**
  - Exact token match as today (`tokens(heard)==tokens(text)`).
  - EXCEPT short lines with ≤ 3 words in `tokens(text)`: accept when token edit distance ≤ 1, or when the difference is punctuation only.
- **Budgets:**
  - Primary engine up to `max_takes` (default 24, in rounds of 4 as today).
  - Fallback engine: new setting `fallback_takes`, default 8, in rounds of 4.
  - The fallback starts only for lines whose primary budget is exhausted without a passing take.
- Backend tests: from `backend/`, `$env:PYTHONIOENCODING='utf-8'; .venv\Scripts\python.exe -m unittest discover -s tests` (387 OK, 48 skipped now). Frontend `npm test` (66).
- Never touch `data/jobs` in tests or acceptance; work on copies under `tmp/p5/`.

## Review Focus
1. A line that passes on neither engine still ends in NeedsReview with a Vietnamese message naming the failed lines. There is no silent bad audio.
2. Cache keys include the engine and its params, so switching the engine or voice never reuses wrong takes, and resuming after a cancel reuses good ones.
3. The OmniVoice subprocess gets offline HF env and a TMP inside the job dir, and its stdout/stderr go to a log. A missing model gives a clear error, not a hang.
4. ECAPA similarity failing (missing model or venv) must not block synthesis. Fall back to duration fit with a warning.
5. A dub speaker with a very short or quiet reference: OmniVoice fallback still gets a usable `ref_audio` and `ref_text`.

### Task 2: Short-line rule + ECAPA similarity + pick order

**Files:** `backend/dubflow/engine_cli.py` (`pick`), new stage `similarity` (speaker venv; reuse the ECAPA loading in `backend/dubflow/speakers.py`), `backend/dubflow/pipeline.py` (`engine()` map: `similarity` → `speaker_python`; choose the accepted take), tests.

**Behavior:**
- `pick` marks each take `passed` (with the short-line rule) and stores `heard`. It no longer chooses the final take on its own.
- After each round, `similarity` scores the passing takes against the line's reference wav: cosine of ECAPA embeddings, both 16 kHz mono, with the take trimmed the same way as pick. It writes `similarity` into `state.json` takes.
- **Choice among passing takes:**
  1. Highest similarity. Takes within 0.02 of the best count as tied.
  2. Among the tied takes, the best duration fit: the take whose trimmed duration fits `cue.end - cue.start` (≤ slot + 0.3 s) with the smallest |slot − duration|. If none fits, the shortest.
- A line is done once it has at least one passing take after a round (as today).
- If the similarity stage fails, log a warning, add it to the job warnings, and choose by duration fit only.
